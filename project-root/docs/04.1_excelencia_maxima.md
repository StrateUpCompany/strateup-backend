# Excelência Máxima — Ações Complementares

---

## 1. Contratos REST — OpenAPI/Swagger

- Adicione um arquivo OpenAPI (ex: `openapi.yaml` ou `swagger.json`) na raiz ou em `/docs/api/`.
- Este arquivo deve descrever todos endpoints, parâmetros, schemas de request/response e códigos de erro.
- Automatize a geração deste arquivo usando ferramentas do framework (ex: Swagger para NestJS, Fastify, Express).

---

## 2. Documentação Dinâmica da API

- Implemente Swagger UI (ou Redoc) no backend para visualização e teste dos endpoints em tempo real.
- Atualize a documentação gerada automaticamente a cada alteração de contrato/endpoints.
- Inclua link para a documentação live no README principal e no frontend (para devs e parceiros).

---

## 3. Diagrama ER Visual

- Mantenha o diagrama do banco em formato visual editável (ex: `.drawio`, `.dbml`, ou `.png` exportado).
- Armazene o arquivo em `/prisma/` ou `/database/` junto ao restante do schema.
- Atualize o diagrama a cada alteração estrutural no banco.
- Inclua instruções no README do banco de como editar e gerar o diagrama.

---

## 4. Scripts de Sanity Check no Banco

- Implemente scripts para:
  - Healthcheck do banco (conexão, integridade mínima)
  - Reindexação periódica (melhora performance)
  - Consistência entre tabelas operacionais e star schema
- Documente como rodar cada script (manual ou automatizado via cron)

---

## 5. READMEs Técnicos

- Mantenha um README atualizado nas principais pastas técnicas:
  - `/prisma/` ou `/database/`: instruções de uso, conventions, como rodar migrations/seeds, como editar o diagrama ER, scripts auxiliares.
  - `/docs/`: índice dos documentos, orientação sobre atualização e governança.
  - `/src/services/`: padrões de implementação, exemplos de uso, conventions de testes.
- O README deve ser claro, objetivo e sempre atualizado junto com o código.

---

> **Atenção:**  
> Estas ações complementam e elevam o padrão de governança, facilitando o onboarding, integração entre times e evolução contínua do backend StrateUp.
