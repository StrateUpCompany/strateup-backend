# Banco de Dados — Arquitetura, Tecnologias e Estrutura

---

## 1. Tecnologias Utilizadas

- **Banco Relacional:** PostgreSQL (robustez, análises, compatibilidade com Star Schema, recursos avançados)
- **ORM/Migrations:** Prisma (TypeScript), ou Sequelize/TypeORM (caso o stack mude), para versionamento, tipagem e governança do schema.
- **Ferramentas complementares:**
  - **DB Diagram:** Para gerar e manter diagramas ER.
  - **Ferramentas de seed:** Para dados default/configuração inicial.
  - **Ferramentas de backup/restore:** Automatizadas para produção.

## 3. Estrutura Lógica do Banco

### 3.1. Schemas/Tabelas Operacionais

- **funnels**            → Funis de vendas/marketing
- **funnel_steps**       → Etapas do funil
- **leads**              → Cadastro de leads
- **diagnostic_answers** → Respostas/diagnóstico dos leads
- **users**              → Usuários do sistema
- **roles**              → Perfis de acesso
- **automations**        → Automações/sequências
- **automation_steps**   → Etapas de automação
- **integrations**       → Integrações externas e chaves

### 3.2. Schemas/Tabelas Analíticas (Star Schema)

- **fact_interactions**  → Fato: eventos de lead, diagnóstico, etapa, automação
- **fact_sales**         → Fato: vendas/fechamentos
- **dim_customer**       → Dimensão: dados do lead/cliente
- **dim_funnel**         → Dimensão: dados dos funis/etapas
- **dim_product**        → Dimensão: produtos/serviços
- **dim_page**           → Dimensão: páginas/landing pages
- **dim_channel**        → Dimensão: canal de origem/contato
- **dim_date**           → Dimensão: data/hora dos eventos

---

## 4. Governança e Boas Práticas

- **Migrations SEMPRE versionadas.** Nenhuma alteração direta no banco.
- **Scripts de seed claros e idempotentes.**
- **Cada branch de feature cria sua migration.**
- **Backup automático e restore testado periodicamente.**
- **Diagrama ER atualizado a cada alteração relevante.**
- **Documentação detalhada das tabelas/campos/relacionamentos.**
- **Scripts de sanity check (health, integridade, indices).**
- **Star Schema atualizado automaticamente via orquestração.**

---

## 5. Observações Finais

- **Nunca misturar dados operacionais com dados analíticos** — sempre manter a separação lógica e física.
- **A pasta do banco é central para o projeto** — qualquer mudança exige PR, code review e atualização de docs.
- **Todo campo, tabela e relacionamento deve estar documentado.**
- **Scripts de manutenção (vacuum, reindex, archiving) devem estar documentados e, se possível, automatizados.**

---

**Com essa estrutura, o banco do StrateUp será robusto, auditável, escalável e pronto para BI avançado e integrações.**
